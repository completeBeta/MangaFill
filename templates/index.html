Settings

Models

Fonts

Lettering face for translated dialogue. Anime Ace (pulled at build) is the default manga look; the bundled OFL fonts are always-available fallbacks.

GPU

CPU only

Vision acceleration (detect / OCR / inpaint) runs on a local GPU when one is available, offloads to a remote GPU worker over HTTP, or falls back to CPU. Translation always stays on the cloud. GPU worker setup guide ↗

General

Auto-detect reads the first page to choose Japanese, Korean, or Chinese. Override it only if detection picks the wrong script.

Translation provider

How long a single translation request may take before it is aborted. Lax by default (300 s) — a degraded provider can answer slowly, and cutting off a slow-but-alive call throws the page away.

Retried automatically on a transient provider error (timeout, connection failure, HTTP 429/5xx, empty completion), with increasing backoff. Default 2.

When the provider is genuinely down, the job stops here and reports why, instead of running to the end leaving pages untranslated. Resume re-runs only the unfinished pages. Default 3.

A page with no vertical dialogue (a cover, a credits or colophon page, or a splash page carrying a 【…】 name-tag) is normally left in Japanese, because those pages were damaged when they ran through erase + lettering. With this on, the configured model reads the crop and translates only in-world captions and name/role tags — a character's name or role shown beside them, which the commercial release does letter. Credits, titles and logos are still left exactly as they are, and so is any caption whose reading cannot be trusted (manga-ocr misreads this stylised text, so a garbled reading is never lettered). Costs one vision call per caption, only on those pages.

English is the default. The list is the engine's own — every language it can render.

Engine

not configured

The translation pipeline itself (detect → OCR → inpaint → lettering) runs in the engine — the upstream manga-image-translator service. This app is the shell around it: jobs, queue, viewer, fonts, CBZ/PDF, logs. Leave the URL empty to use the app's own built-in pipeline instead. One engine container per GPU type (CPU now; CUDA / ROCm images are built from the same engine/ folder).

Advanced

engine knobs — defaults match what this app has always used

These are the engine's own controls. Every value below is the fixed value the app used before the engine existed, so nothing changes until you change it. Detector, resolution, direction and inpainter are the engine's real options; the three fine knobs are free numbers.

The engine only reports text it translated, so anything its detector misses — the tail of a line, vertical Japanese — is never erased and stays visible under the English. With the second pass on, this app's own detector finds those regions and translates them too (a few blocks per page). It is skipped automatically when the host is low on memory, and the reason is written to the job's log line.

Our typesetter = the engine detects, reads and translates the page, and this app draws the text with its own lettering — fitted to each balloon's outline and filling it, which is the look this app was finished with. Engine's own lets upstream render the whole page instead (its text sits in the detected box rather than filling the shape).
